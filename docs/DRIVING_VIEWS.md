# 2.17.4: Spa clearance, driving cameras and instruments

Spa's former raster-based chassis clearance remained at +0.19m even after 2.17.3 switched asphalt contact to actual triangles. On the new accurate road surface this visibly raised the tyres. The plane-fit height and raw-height floor now use +0.005m; the ride filter uses the same floor. The RB22 model minimum Y is zero, so its old +0.075m model-origin lift is also removed on Spa for both player and ghost, with matching shadow alignment. SF26 retains its calibrated +0.5m origin (source minimum Y -0.4983m). Original slope following and damped kerb/road feedback are retained. Curved crests may still require visual calibration in a full driving lap.

Chase camera default boom is 6.8m back and 2.25m high (previously 10.5m / 4.7m). Speed/braking transitions remain smoothed. The boom follows Spa's slope and keeps terrain clearance. Existing venue wall geometry shortens the boom when a wall crosses the line behind the car. This is wall avoidance using current collision data, not a complete collision mesh for every bridge, roof or decorative object.

Five V-key views: Chase, Cockpit, Halo / T-Cam, Front wing, Rear. Halo uses a chassis-relative mount 1.12m above road, 0.35m behind the car reference, looking down eight degrees; it follows pitch/roll using the same transform as the cockpit. Existing RB22/SF26 cockpit mounts remain unchanged. Mount calibration is approximate until model-specific Blender markers are supplied.

The bottom-centre HUD shows km/h, N/R and virtual automatic forward gears 1–8. Forward gears use speed thresholds and 8km/h downshift hysteresis; light progression follows progress within each gear. No physical gearbox or engine RPM is simulated by this display. Pauses freeze speed; quit hides the HUD; a new grid starts in N. Legacy hidden telemetry IDs are retained for existing instrumentation.

Checks: camera unit tests cover five-view order and Halo chassis alignment; contact tests and all 28 resource checks pass. `tools/driving_views_smoke.py` checks RB22/SF26 at Spa, ground clearance, chase height, Halo selection, V cycling, N/forward/R HUD readings and browser errors; it saves side/chase/Halo screenshots for visual review. `tools/camera_smoke.py` includes the new view in its cycling sequence. Windows file:// opening remains outside cloud-browser validation.

Validation outcome: RB22 and SF26 browser scenarios passed, including side/chase/Halo screenshot inspection. Original GLB accessor bounds confirmed RB22 minimum Y=0 and SF26 minimum Y=-0.498330444. Browser tests verified five-view cycling, corrected Spa body-bottom clearance, lower chase height, and N/1/3/7/R HUD states with no uncaught exceptions. Camera unit tests (5), contact tests and all 28 asset integrity checks passed. Full laps and every overhead building remain outside this targeted validation.
